# Генератор тестов для ЭИОС (quiz-generator)

Проект по практике для ИМЭС РУДН. Приложение на Streamlit, которое готовит тестовые
вопросы для Moodle и экспортирует их в Aiken, Moodle XML, QTI 1.2, JSON и Excel.

## Три раздела

| Раздел | Что делает | Откуда вопросы | Ответ определяет |
|---|---|---|---|
| **Тест из реестра** | берёт файл преподавателя из реестра в Moodle, готовит тест до 25 вопросов, отправляет результат обратно в реестр и в банк вопросов курса | из файла, ИИ ничего не придумывает | пометка в файле (слова, знаки, ключ, жирный, цвет, подчёркивание, маркер) |
| **Тест из файла** | то же, но файл загружается вручную, а номер курса вводится при отправке | из файла | пометка в файле |
| **Тест из лекции** | придумывает новые вопросы по PDF лекции | придумывает ИИ | ИИ, нужна проверка человеком |

В разделе «Тест из файла» есть переключатель: слева «Режим одного верного ответа», справа
«Режим всех типов вопросов». Правый режим работает без лимита 25 (эссе, соответствие,
Excel/QTI/JSON), но без отправки в Moodle.

### Общий поток для файла преподавателя

Преподаватель присылает файл с готовыми вопросами (Word, PDF, текст или Aiken, оформление
любое), сотрудник ИМЭС получает тест в Aiken и Moodle XML.

- Берутся первые 25 подходящих вопросов (один верный ответ, 2–6 вариантов). Если их меньше,
  приложение сообщает, сколько не хватает.
- Ничего не теряется молча: отчёт показывает, какие вопросы пропущены и почему (нет пометки
  ответа, несколько верных, нет вариантов, ошибка формата Aiken).
- ИИ **не выбирает ответ сам**: он переносит пометку из файла и называет цитату-основание
  (список «Как определены правильные ответы» для проверки глазами).
- Файл в формате Aiken читается кодом, без ИИ, бесплатно.
- После запуска показываются токены и примерная стоимость; есть лимит расхода на файл
  (подробности в [docs/DETAILS.md](docs/DETAILS.md)).

## Moodle: реестр, банк вопросов и создание теста

Шаг «Отправьте в Moodle» (белая карточка) работает через веб-сервисы Moodle 4.5+. Приложение
запускается у себя на компьютере (`localhost`) и ходит в Moodle по токену; внутри Moodle ничего
не живёт, кроме реестра и плагина.

- **Реестр** это элемент «База данных» в отдельном курсе: одна запись на курс (наименование,
  ссылка на курс, вид контроля, группы и преподаватели через запятую, файл от преподавателя,
  два файла результата, статус, отчёт). Приложение находит поля **по названию колонки**,
  поэтому колонки нельзя переименовывать. Курс и название реестра задаются в `.env`
  (`MOODLE_REGISTRY_COURSE`, `MOODLE_REGISTRY_NAME`). Заготовка структуры импортируется как пресет.
- **Номер курса** в шаге отправки берётся из записи реестра, но его можно поправить прямо в
  поле «Номер курса» (например, если курса из реестра нет на тестовой ЭИОС). Под полем
  показано название курса (нужна функция `core_course_get_courses_by_field` в службе).
- **«Добавить обработанный файл в базу данных»** кладёт в запись файлы Moodle XML и Aiken,
  статус «Обработан» и отчёт.
- **«Загрузить вопросы в банк вопросов курса»** отправляет вопросы в банк вопросов курса, в папку
  (по умолчанию «Промежуточная аттестация 2026»). Плагин дубли не отсеивает, поэтому приложение
  помнит загрузки (`data/moodle_uploads.json`) и предупреждает о повторе. Неполный результат
  (остановка по лимиту) и пустой тест отправить нельзя.
- **«Создать тест в курсе»** создаёт сам элемент «Тест» в разделе «Промежуточная аттестация»
  (раздел ищется по названию), загружает в него вопросы и показывает ссылку. Статус записи
  реестра меняется на «Загружен в курс», ссылка попадает в отчёт.

### Настройки теста по умолчанию

Настройки видны в блоке «Настройки теста в курсе» и меняются перед созданием.

| Параметр | По умолчанию |
|---|---|
| Название | «Промежуточная аттестация: {название курса}» |
| Баллы | 2 за вопрос, до 25 вопросов → 50 за тест; проходного балла нет |
| Время | 40 минут |
| Попытки | 1 |
| Перемешивание | вопросов и вариантов ответа: да |
| Вопросов на странице | 1, свободная навигация |
| Режим | отложенный отзыв, оценки показываются |
| Способ оценивания | «Высшая оценка» |
| Видимость | **скрыт** от студентов (флажок «Сразу показать тест студентам» выключен) |

Значения временные: окончательные (название, даты, время, попытки, что видит студент, пароль)
согласуются с ИМЭС.

### Плагин local_qbankremotemanager

Загрузка вопросов и создание теста выполняются плагином Moodle
`local_qbankremotemanager` (GPL v3, Moodle 4.1+; плагин чужой, в этот
репозиторий не входит). Нужны его функции `am_i_here`, `upload_questions`, `upload_quiz`,
`get_question_categories`, а также `core_course_get_contents` и `core_course_get_courses_by_field`
в службе веб-сервисов.

Права для учётной записи токена: `mod/quiz:addinstance`, `mod/quiz:manage`,
`moodle/question:add`, `moodle/question:editall`, `moodle/question:managecategory`,
`moodle/question:moveall`, `moodle/question:useall`. На тестовой ЭИОС токен выдан администратору,
на боевой нужна отдельная учётная запись с этим минимумом.

Если на сайте установлено дополнение **quizaccess_supervisedcheck** (блок «Надзор»), оригинальный
плагин падает с ошибкой `Column 'supervisedmode' cannot be null`: он не заполняет его поля.
Мы использовали версию `1.2.0-imes1`: в конфигурацию добавлены `supervisedmode` (0) и
`lessontypeid` (-1). Правка небольшая (две строки в `classes/external/qbankremotemanager_external.php`),
перед установкой на боевую ЭИОС её должен просмотреть программист ИМЭС.

### Проверка без интерфейса

```bash
python3 -m scripts.moodle_check --course 16                     # связь и пробная загрузка 3 вопросов в банк
python3 -m scripts.moodle_quiz_check --course 16                # связь, плагин, раздел, пробный СКРЫТЫЙ тест
python3 -m scripts.moodle_db_check --registry-course 17         # чтение реестра (только чтение)
python3 -m scripts.moodle_db_write_check --registry-course 17 --entry 1   # пробная запись (меняет запись!)
```

Токен Moodle хранится только в `.env`. Скрипты с пометкой «проба» создают в курсе реальные
(скрытые) тесты: после проверки их стоит удалить.

## Форматы экспорта

| Формат | Типы вопросов | Заметки |
|---|---|---|
| Moodle XML | все 5 | родной формат Moodle, **импорт подтверждён на практике** |
| Aiken | выбор и верно/неверно | простой текст; пояснения не сохраняет; импорт подтверждён |
| QTI 1.2 | все 5 | Moodle его не опознал, может пригодиться для других LMS |
| JSON, Excel | все 5 | хранение, обмен и ручная правка |

Импорт в Moodle: Банк вопросов → Импорт → формат Aiken или Moodle XML.

## Установка и запуск

```bash
git clone <url> && cd quiz-generator
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# открыть .env и вписать BOTHUB_API_KEY (bothub.chat → «Для разработчиков»)
# для Moodle: MOODLE_URL, MOODLE_TOKEN, MOODLE_REGISTRY_COURSE (см. раздел «Moodle»)

streamlit run app.py
```

Тесты: `pip install -r requirements-dev.txt`, затем `python3 -m pytest -q` (реальных вызовов API нет). 
Образцы файлов «как от преподавателей»: `python3 scripts/make_teacher_samples.py` → `data/sample/teacher_files/`.
Настройки Streamlit (тёмная тема, без телеметрии, доступ только с этого компьютера) — в `.streamlit/config.toml`.

## Стек

Python · Streamlit · pdfplumber и python-docx (чтение файлов) · BotHub API через SDK `openai`
(модель `claude-sonnet-5`) · Pydantic · openpyxl · xml.etree.

## Известные особенности

- **BotHub игнорирует системное сообщение** для `claude-sonnet-5`: инструкция до модели не
  доходит, она отвечает обычным текстом, и разбор JSON падает (в таблице расхода видно ~400
  входных токенов вместо ~2000). Поэтому по умолчанию инструкция и текст файла отправляются
  одним сообщением (`BOTHUB_SYSTEM_IN_USER=1`). Диагностика: `python3 -m scripts.bothub_probe`
  (три крошечных запроса, стоят доли копейки). Если ошибка «модель ответила не JSON» повторяется,
  проверьте, что в `.env` нет строки `BOTHUB_SYSTEM_IN_USER=0`.
- **Язык сайта и способ оценивания.** Moodle принимает название способа оценивания на языке
  сайта; приложение передаёт «Высшая оценка». На сайте с другим языком значение нужно поменять.
- **Плагин не защищает от дублей.** Повторное создание теста создаёт второй тест; приложение
  предупреждает о повторе по журналу `data/moodle_uploads.json`.
- **Автоповторов запросов к ИИ нет** (защита от скрытых списаний): при невалидном ответе
  модели файл можно обработать заново кнопкой.

## Приватность

- Реальные лекции и файлы преподавателей **не хранятся в репозитории**
  (`data/uploads/`, `data/output/` в `.gitignore`); в `data/sample/` — только выдуманные образцы.
- Ключ BotHub и токен Moodle лежат в `.env`, который в `.gitignore` и не попадает в git;
  в репозитории только заглушки (`.env.example`, адрес `your-moodle.example`).
- Журнал загрузок `data/moodle_uploads.json` тоже в `.gitignore`.
- Файл преподавателя из реестра скачивается только в память, на диск не сохраняется.
- Streamlit работает только на `localhost`, телеметрия отключена.
- Текст загруженного файла (кроме файлов Aiken) отправляется в BotHub для обработки моделью.
  Не загружайте файлы с персональными данными студентов; допустимость передачи материалов
  стоит согласовать с ИМЭС.
