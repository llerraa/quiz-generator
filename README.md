# Генератор тестов для ЭИОС (quiz-generator)

Приложение на Streamlit для ИМЭС: готовит тестовые вопросы для Moodle (ЭИОС), экспортирует их
в Aiken, GIFT, Moodle XML и JSON и создаёт тест в курсе.

## Разделы

| Раздел | Что делает |
|---|---|
| **Тест из реестра** | берёт файл преподавателя из реестра в Moodle, готовит до 25 вопросов, пишет результат в реестр, загружает в банк вопросов и создаёт тест в курсе |
| **Тест из файла** | то же, но файл загружается вручную, номер курса вводится при отправке |
| **Тест из лекции** | ИИ придумывает вопросы по PDF лекции (нужна проверка человеком) |

## Файл преподавателя

- Форматы: Word, PDF, текст, Aiken. Берутся первые 25 подходящих вопросов (2–6 вариантов, один или два верных ответа: `ANSWER: B,D`).
- Верный ответ определяет только пометка в файле; ИИ ответ не выбирает. Файл Aiken читается кодом, без ИИ.
- Пропущенные вопросы перечисляются в отчёте с причинами.
- Меньше 25 вопросов: тест не создаётся, вопросы в курс не загружаются, запись получает статус «Отправлен на доработку (тест не сформирован)».

## Moodle

Приложение работает на `localhost` и ходит в Moodle по токену (веб-сервисы, Moodle 4.5+).

- **Реестр** — элемент «База данных» (курс и название задаются в `.env`: `MOODLE_REGISTRY_COURSE`, `MOODLE_REGISTRY_NAME`). Колонки находятся по названию: наименование курса, ссылка на курс, вид контроля, группа, преподаватель, кафедра, «Файл от зав кафедрой», «Статус», «Проверенный файл» (Aiken), «Файл (Gift) для заливки», отчёт. Записи показаны таблицей с фильтрами и сортировкой.
- **Статусы:** «Не обработан», «Загружен в банк вопросов курса», «Тест сформирован в курсе», «Отправлен на доработку (тест не сформирован)».
- **Исключения:** если в колонке «Исключения» что-то указано (тест не нужен, несколько тестов), запись обрабатывается вручную. В приложении такие записи по умолчанию скрыты, а при выборе показывают предупреждение и тест для них не готовится.
- **Фильтры таблицы:** статус, файл от зав кафедрой, вид контроля, кафедра, исключения, поиск по курсу, группе, преподавателю и номеру курса.
- **Кнопки:** «Добавить обработанный файл в базу данных», «Загрузить вопросы в банк вопросов курса», «Создать тест в курсе», «Отправить на доработку». При нехватке вопросов первые две загрузки и создание теста заблокированы.
- **Тест в курсе** создаётся скрытым, в разделе «Промежуточная аттестация», в категории журнала «ПРОМЕЖУТОЧНАЯ АТТЕСТАЦИЯ…», с идентификационным номером **`ПА-тест`** (одинаков везде). Название: «Тест. Промежуточная аттестация по дисциплине {название}» (из «Полей из 1С»: «Название дисциплины» или `discipline_name`).
- **Формулу итога категории журнала приложение не меняет:** менеджеры правят её вручную (`=[[Э/З]]+[[ПА-тест]]`).
- **Предохранители:** приложение вызывает только 11 заранее заданных функций Moodle (записывающих три: загрузка вопросов, создание теста, обновление записи реестра) и отправляет в плагин только список разрешённых параметров. Формулы журнала и любые другие изменения журнала в этот список не входят.
- **«Рубильники» в Moodle** (немедленно остановить работу приложения без его правки): запретить изменение базы данных, запретить создание тестов, отключить службу целиком, отозвать токен. Пошагово: [docs/DETAILS.md](docs/DETAILS.md#рубильники-в-moodle).

Настройки теста по умолчанию (меняются перед созданием): 2 балла за вопрос (до 50), 40 минут, 1 попытка, вопросы и варианты перемешиваются, отложенный отзыв, оценка видна, проходного балла нет, способ оценивания «Высшая оценка».

### Плагин `local_qbankremotemanager` (версия `1.2.0-imes2`)

Тест создаёт и вопросы загружает плагин Moodle (GPL v3, чужой, в репозиторий не входит). Локальные правки:
`supervisedmode`/`lessontypeid` (для `quizaccess_supervisedcheck`) и `cmidnumber` (идентификационный номер теста).
Категорию журнала плагин принимает по названию (`gradecat`).

- Нужны функции `am_i_here`, `upload_questions`, `upload_quiz`, `get_question_categories`, а также `core_course_get_contents`, `core_course_get_courses_by_field` в службе.
- Права токена: `mod/quiz:addinstance`, `mod/quiz:manage`, `moodle/question:add`, `editall`, `managecategory`, `moveall`, `useall`.
- **Обновлять плагин на месте, не удаляя:** при удалении слетают функции в службе. Порядок: заменить папку `local/qbankremotemanager`, «Уведомления» → обновить, очистить кеши, проверить функции в службе.
- Со старым плагином тест создаётся без номера, приложение предупреждает.

## Форматы экспорта

Moodle XML, Aiken, GIFT (выбор с 1–2 верными ответами и верно/неверно), JSON. У двух верных ответов в XML и GIFT веса +50 / −50.

## Установка и запуск

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env     # вписать BOTHUB_API_KEY, MOODLE_URL, MOODLE_TOKEN, MOODLE_REGISTRY_COURSE
streamlit run app.py
```

Тесты: `pip install -r requirements-dev.txt`, затем `python3 -m pytest -q`.

## Структура

```
app.py             # интерфейс Streamlit
src/moodle/        # клиент веб-сервисов, реестр, панель отправки, журнал загрузок
src/parsing/       # PDF, Word, Aiken
src/exporters/     # Moodle XML, Aiken, GIFT, JSON
src/llm/           # запросы к BotHub
src/course_pipeline.py  # отбор до 25 вопросов, отчёт
src/injection_guard.py  # проверка ответа модели на следы промпт-инъекции
scripts/ tests/ docs/ data/sample/
```

## Особенности

- BotHub игнорирует системное сообщение для `claude-sonnet-5`, поэтому инструкция и текст идут одним сообщением (`BOTHUB_SYSTEM_IN_USER=1`). Диагностика: `python3 -m scripts.bothub_probe`.
- Плагин не защищает от дублей: приложение предупреждает о повторе по `data/moodle_uploads.json`.
- Идентификационный номер уникален в курсе; если он занят, ошибка называет держателя.
- Защита от промпт-инъекций: текст файла идёт между метками `[ДАННЫЕ_НАЧАЛО]`/`[ДАННЫЕ_КОНЕЦ]`, модели сказано не выполнять его; ответ проверяется на подозрительные фразы (`src/injection_guard.py`), а при находке отправка в Moodle блокируется, пока человек не подтвердит проверку. Подробнее: [docs/DETAILS.md](docs/DETAILS.md#защита-от-промпт-инъекций).
- Токены и ключи только в `.env` (в `.gitignore`); реальные файлы не хранятся в репозитории.
