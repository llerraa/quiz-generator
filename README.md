# Генератор тестовых вопросов из PDF-лекций

Проект по практике для ИМЭС — приложение для преподавателей: загружаешь PDF
лекции, получаешь тестовые вопросы (множественный выбор, верно/неверно,
на соответствие), сгенерированные ИИ, с просмотром в браузере и экспортом
в JSON/Excel/QTI.

Второй режим — «Привести готовые вопросы к формату»: если у преподавателя
уже есть готовые вопросы в docx/pdf/тексте, приложение распознаёт их и
приводит к той же структуре (не генерирует новые, а именно извлекает
существующие).

## Стек

- **Python** — pdfplumber (парсинг PDF), python-docx (парсинг Word),
  BotHub API через SDK `openai` (генерация и извлечение вопросов)
- **Streamlit** — интерфейс для преподавателя, в фирменном стиле ИМЭС
- **openpyxl** — экспорт в Excel
- **xml.etree** (встроено в Python) — экспорт в QTI 1.2

## Про BotHub

Изначально использовался GigaChat API, но перешли на **BotHub**
(bothub.chat) — российский агрегатор с оплатой рублями, дающий доступ
к разным моделям (Claude, GPT и др.) через один OpenAI-совместимый API.
Сейчас в проекте используется `claude-sonnet-5`.

**Важный технический нюанс**: параметру `response_format` (стандартный
способ в OpenAI SDK попросить структурированный JSON-ответ) через BotHub
доверять нельзя — на практике модель может просто проигнорировать его и
ответить обычным текстом (см. `src/llm/bothub_client.py`). Поэтому формат
ответа запрашивается явно текстом в самом промпте, а JSON разбирается и
валидируется вручную, с защитой от markdown-обёртки и лишнего текста
вокруг.

## Установка

```bash
# 1. Клонировать репозиторий и перейти в папку проекта
git clone <url> && cd quiz-generator

# 2. Создать окружение и поставить зависимости
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 3. Настроить ключ BotHub
cp .env.example .env
# открыть .env и вписать реальный BOTHUB_API_KEY
# (получить в личном кабинете bothub.chat → "Для разработчиков")

# 4. Запустить интерфейс
streamlit run app.py
```

Настройки Streamlit (тёмная тема, отключённая телеметрия, запрет доступа
с других устройств в сети) уже лежат в `.streamlit/config.toml`.

## Известное ограничение: точность правильного ответа

LLM иногда может указать неверный индекс правильного варианта в вопросах
с множественным выбором, даже когда собственное объяснение модели указывает
на другой вариант — отловить это кодом полностью нельзя. У каждого вопроса
с множественным выбором есть поле `explanation` (видно и в интерфейсе, и
в JSON) — объяснение модели для быстрой проверки человеком. Перед
использованием сгенерированных вопросов со студентами рекомендуется
просмотреть их — это заложено и в текст самого интерфейса.

## Про парсинг PDF

Модуль `pdf_parser.py` покрывает **цифровые PDF** (презентации/лекции
с текстовым слоем — типичный экспорт из PowerPoint/Word/LaTeX), извлекает
текст обычным `extract_text()` (без `layout=True` — на реальных
PowerPoint-экспортах этот режим давал огромное количество пробелов вместо
текста).

Если на реальных материалах ИМЭС встретятся страницы без текстового слоя
(сканы), парсер их не сломает, но пометит флагом `likely_scanned=True` —
задокументированный триггер для подключения OCR (pytesseract) отдельным
модулем позже, если понадобится.

## Приватность данных

- Реальные лекционные материалы ИМЭС **не хранятся в репозитории**
  (`data/uploads/`, `data/output/` в `.gitignore`) — только обезличенные
  тестовые файлы в `data/sample/`.
- Ключ BotHub хранится в `.env`, который в `.gitignore` и никогда не
  попадает в git.
- Streamlit запускается только на `localhost`, анонимная телеметрия
  отключена (`.streamlit/config.toml`).
