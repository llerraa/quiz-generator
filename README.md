# Генератор тестовых вопросов из PDF-лекций

Проект по практике для ИМЭС — приложение для преподавателей: загружаешь PDF
лекции, получаешь тестовые вопросы (множественный выбор, верно/неверно,
на соответствие, эссе, короткий ответ), сгенерированные ИИ, с просмотром
в браузере и экспортом в JSON, Excel, QTI 1.2, Moodle XML и Aiken.

Второй режим — «Привести готовые вопросы к формату»: если у преподавателя
уже есть готовые вопросы в docx/pdf/тексте, приложение распознаёт их и
приводит к той же структуре (не генерирует новые, а именно извлекает
существующие). Если файл с вопросами в формате Aiken (.txt), приложение
читает его обычным кодом, без обращения к ИИ — бесплатно и без риска, что
модель что-то «додумает».

## Режим «Тест для курса»

Основной сценарий для сессии в ЭИОС: преподаватель кладёт в курс файл с готовыми
вопросами, сотрудник ИМЭС загружает его в приложение и получает тест до 25 вопросов
в формате Aiken (один верный ответ) и в Moodle XML.

- Файл может быть PDF, Word или текстом, в любом оформлении. Правильный ответ
  распознаётся по словам («Ответ: Б»), знакам (`*`, `+`), ключу в конце файла и по
  **оформлению**: жирный шрифт, подчёркивание, выделение маркером, цвет
  (в PDF — жирный и цвет).
- Файл в формате Aiken читается кодом, без ИИ.
- ИИ **не выбирает ответы сам**: он только переносит пометки из файла и называет
  цитату-основание. Нет пометки — вопрос пропускается.
- Берутся первые 25 подходящих вопросов. Остальное приложение не теряет молча,
  а показывает отчёт: сколько вошло, что пропущено и почему (нет пометки ответа,
  несколько верных ответов, число вариантов не 2–6, нет вариантов ответа, ошибка
  формата Aiken). Если вопросов меньше 25, сообщается, сколько не хватает.
- Для проверки есть список «Как определены правильные ответы» — по какой пометке
  выбран ответ каждого вопроса.

Образцы файлов в разных стилях для проверки на настоящей модели:
`python scripts/make_teacher_samples.py` → `data/sample/teacher_files/`.

## Форматы экспорта

| Формат | Какие типы вопросов | Заметки |
|---|---|---|
| JSON | все 5 | для хранения и обмена |
| Excel | все 5 | для просмотра и ручной правки |
| Moodle XML | все 5 | родной формат Moodle, **импорт подтверждён на практике** |
| QTI 1.2 | все 5 | Moodle его не опознал («в файле нет вопросов»), может пригодиться для других LMS |
| Aiken | только множественный выбор и верно/неверно | простой текст для импорта в Moodle; пояснения не сохраняет |

Про Aiken: в нём нет места для соответствия, эссе и короткого ответа, поэтому
такие вопросы в файл не попадают. Приложение не молчит об этом: рядом с кнопкой
скачивания показывается, сколько вопросов не вошло. Вопрос «верно/неверно»
записывается как вопрос с двумя вариантами «Верно» и «Неверно». Импорт в Moodle:
Банк вопросов → Импорт → формат Aiken.

## Стек

- **Python** — pdfplumber (парсинг PDF), python-docx (парсинг Word),
  BotHub API через SDK `openai` (генерация и извлечение вопросов)
- **Streamlit** — интерфейс для преподавателя, в фирменном стиле ИМЭС
- **openpyxl** — экспорт в Excel
- **xml.etree** (встроено в Python) — экспорт в QTI 1.2 и Moodle XML

## Про BotHub

Изначально использовался GigaChat API, но перешли на **BotHub**
(bothub.chat) — российский агрегатор с оплатой рублями, дающий доступ
к разным моделям (Claude, GPT и др.) через один OpenAI-совместимый API.
Сейчас в проекте используется `claude-sonnet-5`.

**Важный технический нюанс**: параметру `response_format` (стандартный
способ в OpenAI SDK попросить структурированный JSON-ответ) через BotHub
доверять нельзя — на практике модель может просто проигнорировать его и
ответить обычным текстом (см. `src/llm/bothub_client.py`). Поэтому формат
ответа запрашивается явно текстом в самом промпте, а JSON разбирается и
валидируется вручную, с защитой от markdown-обёртки и лишнего текста
вокруг.

### Расход и защита от лишних трат

- После каждого запуска режима «Тест для курса» приложение показывает, сколько запросов
  ушло к ИИ, сколько токенов (вход и выход) и примерную стоимость в CAPS и рублях.
  Файлы обрабатываются по одному: одно нажатие «Подготовить тест» — один файл.
  Файл Aiken читается без ИИ и ничего не стоит.
- Оценка считается по тарифу из `.env` (`BOTHUB_CAPS_PER_INPUT_TOKEN`,
  `BOTHUB_CAPS_PER_OUTPUT_TOKEN`, `BOTHUB_RUB_PER_CAP`). Это прикидка; точное
  списание смотрите в личном кабинете BotHub.
- Файл длиннее `COURSE_MAX_CHARS` символов (по умолчанию 60 000) ИИ не обрабатывает:
  кнопка заблокирована и показано объяснение.
- Лимит расхода на один файл — `COURSE_MAX_CAPS` (по умолчанию 9 000 CAPS ≈ 0,9 ₽). Как только
  файл «съел» столько, запросы к ИИ прекращаются, приложение пишет «Превышен лимит токенов
  на один файл» и показывает то, что успело найти (помечено как неполный результат).
  Проверка идёт между запросами: уже отправленный запрос остановить нельзя.
- Скрытые автоматические повторы запросов отключены (`max_retries=0`), чтобы один сбой
  сети не превращался в тихие повторные списания.
- Если расход пошёл не туда: `Ctrl+C` в терминале останавливает приложение;
  главный тормоз — отозвать ключ в личном кабинете BotHub. Держите на балансе небольшую
  сумму и не включайте автопополнение.

## Установка

```bash
# 1. Клонировать репозиторий и перейти в папку проекта
git clone <url> && cd quiz-generator

# 2. Создать окружение и поставить зависимости
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 3. Настроить ключ BotHub
cp .env.example .env
# открыть .env и вписать реальный BOTHUB_API_KEY
# (получить в личном кабинете bothub.chat → "Для разработчиков")

# 4. Запустить интерфейс
streamlit run app.py
```

Настройки Streamlit (тёмная тема, отключённая телеметрия, запрет доступа
с других устройств в сети) уже лежат в `.streamlit/config.toml`.

## Известное ограничение: точность правильного ответа

LLM иногда может указать неверный индекс правильного варианта в вопросах
с множественным выбором, даже когда собственное объяснение модели указывает
на другой вариант — отловить это кодом полностью нельзя. У каждого вопроса
с множественным выбором есть поле `explanation` (видно и в интерфейсе, и
в JSON) — объяснение модели для быстрой проверки человеком. Перед
использованием сгенерированных вопросов со студентами рекомендуется
просмотреть их — это заложено и в текст самого интерфейса.

## Про парсинг PDF

Модуль `pdf_parser.py` покрывает **цифровые PDF** (презентации/лекции
с текстовым слоем — типичный экспорт из PowerPoint/Word/LaTeX), извлекает
текст обычным `extract_text()` (без `layout=True` — на реальных
PowerPoint-экспортах этот режим давал огромное количество пробелов вместо
текста).

Если на реальных материалах ИМЭС встретятся страницы без текстового слоя
(сканы), парсер их не сломает, но пометит флагом `likely_scanned=True` —
задокументированный триггер для подключения OCR (pytesseract) отдельным
модулем позже, если понадобится.

## Приватность данных

- Реальные лекционные материалы ИМЭС **не хранятся в репозитории**
  (`data/uploads/`, `data/output/` в `.gitignore`) — только обезличенные
  тестовые файлы в `data/sample/`.
- Ключ BotHub хранится в `.env`, который в `.gitignore` и никогда не
  попадает в git.
- Streamlit запускается только на `localhost`, анонимная телеметрия
  отключена (`.streamlit/config.toml`).
