# Генератор тестов для ЭИОС (quiz-generator)

Проект по практике для ИМЭС РУДН. Приложение на Streamlit, которое готовит тестовые
вопросы для Moodle и экспортирует их в Aiken, Moodle XML, QTI 1.2, JSON и Excel.

## Три раздела

| Раздел | Что делает | Откуда вопросы | Ответ определяет |
|---|---|---|---|
| **Тест из реестра** | берёт файл преподавателя из реестра в Moodle, готовит тест до 25 вопросов, отправляет результат обратно в реестр и в банк вопросов курса | из файла, ИИ ничего не придумывает | пометка в файле (слова, знаки, ключ, жирный, цвет, подчёркивание, маркер) |
| **Тест из файла** | то же, но файл загружается вручную, а номер курса вводится при отправке | из файла | пометка в файле |
| **Тест из лекции** | придумывает новые вопросы по PDF лекции | придумывает ИИ | ИИ, нужна проверка человеком |

В разделе «Тест из файла» есть переключатель: слева «Режим одного верного ответа», справа
«Режим всех типов вопросов». Правый режим работает без лимита 25 (эссе, соответствие,
Excel/QTI/JSON), но без отправки в Moodle.

### Общий поток для файла преподавателя

Преподаватель присылает файл с готовыми вопросами (Word, PDF, текст или Aiken, оформление
любое), сотрудник ИМЭС получает тест в Aiken и Moodle XML.

- Берутся первые 25 подходящих вопросов (один верный ответ, 2–6 вариантов). Если их меньше,
  приложение сообщает, сколько не хватает.
- Ничего не теряется молча: отчёт показывает, какие вопросы пропущены и почему (нет пометки
  ответа, несколько верных, нет вариантов, ошибка формата Aiken).
- ИИ **не выбирает ответ сам**: он переносит пометку из файла и называет цитату-основание
  (список «Как определены правильные ответы» для проверки глазами).
- Файл в формате Aiken читается кодом, без ИИ, бесплатно.
- После запуска показываются токены и примерная стоимость; есть лимит расхода на файл
  (подробности в [docs/DETAILS.md](docs/DETAILS.md)).

## Moodle: реестр и загрузка в курс

Шаг «Отправьте в Moodle» (белая карточка) работает через веб-сервисы Moodle 4.5+.

- **Реестр** это элемент «База данных» в отдельном курсе: одна запись на курс (наименование,
  ссылка на курс, вид контроля, группы и преподаватели через запятую, файл от преподавателя,
  два файла результата, статус, отчёт). Приложение находит поля **по названию колонки**,
  поэтому колонки нельзя переименовывать. Заготовка структуры импортируется как пресет. В шаге отправки показано название курса
  (нужна функция `core_course_get_courses_by_field` в службе; без неё название не показывается).
- **«Добавить обработанный файл в базу данных»** кладёт в запись файлы Moodle XML и Aiken, статус «Обработан» и отчёт.
- **«Загрузить вопросы в банк вопросов курса»** отправляет вопросы в банк вопросов курса, в папку (по умолчанию
  «Промежуточная аттестация 2026»). Плагин дубли не отсеивает, поэтому приложение помнит
  загрузки (`data/moodle_uploads.json`) и предупреждает о повторе. Неполный результат
  (остановка по лимиту) и пустой тест отправить нельзя.
- Токен Moodle хранится только в `.env`. Для боевой ЭИОС нужна отдельная учётная запись
  с минимальными правами.

Проверка связи без интерфейса:

```bash
python -m scripts.moodle_check --course 16                    # связь и пробная загрузка 3 вопросов
python -m scripts.moodle_db_check --registry-course 17        # чтение реестра (только чтение)
python -m scripts.moodle_db_write_check --registry-course 17 --entry 1   # пробная запись (меняет запись!)
```

## Форматы экспорта

| Формат | Типы вопросов | Заметки |
|---|---|---|
| Moodle XML | все 5 | родной формат Moodle, **импорт подтверждён на практике** |
| Aiken | выбор и верно/неверно | простой текст; пояснения не сохраняет; импорт подтверждён |
| QTI 1.2 | все 5 | Moodle его не опознал, может пригодиться для других LMS |
| JSON, Excel | все 5 | хранение, обмен и ручная правка |

Импорт в Moodle: Банк вопросов → Импорт → формат Aiken или Moodle XML.

## Установка и запуск

```bash
git clone <url> && cd quiz-generator
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# открыть .env и вписать BOTHUB_API_KEY (bothub.chat → «Для разработчиков»)
# для Moodle: MOODLE_URL, MOODLE_TOKEN, MOODLE_REGISTRY_COURSE (см. раздел «Moodle»)

streamlit run app.py
```

Тесты: `python3 -m pytest -q` (реальных вызовов API нет). Образцы файлов «как от
преподавателей»: `python3 scripts/make_teacher_samples.py` → `data/sample/teacher_files/`.
Настройки Streamlit (тёмная тема, без телеметрии, доступ только с этого компьютера) — в
`.streamlit/config.toml`.

## Стек

Python · Streamlit · pdfplumber и python-docx (чтение файлов) · BotHub API через SDK `openai`
(модель `claude-sonnet-5`) · Pydantic · openpyxl · xml.etree.

## Структура

```
app.py                    # интерфейс Streamlit: три раздела, отчёты, экспорт, шаг «Отправить в Moodle»
src/
  course_pipeline.py      # режим «Тест для курса»: отбор до 25 вопросов, отчёт о пропущенном
  budget.py               # остановка при превышении лимита расхода на файл
  config.py               # настройки из .env
  models.py               # схема вопросов (5 типов)
  ui_modes.py             # названия и короткие описания трёх разделов
  moodle/                 # клиент веб-сервисов, чтение/запись реестра, журнал загрузок, блоки интерфейса
  parsing/                # PDF, Word (с метками оформления), Aiken, определение кодировки
  llm/bothub_client.py    # запросы к BotHub, учёт токенов
  exporters/              # JSON, Excel, QTI, Moodle XML, Aiken
scripts/                  # образцы файлов, диагностика PDF, проверка BotHub и Moodle
tests/                    # автотесты
docs/DETAILS.md           # расход и замеры, BotHub, парсинг PDF
data/sample/              # обезличенные образцы (реальные материалы — не сюда)
```

## Приватность

- Реальные лекции и файлы преподавателей **не хранятся в репозитории**
  (`data/uploads/`, `data/output/` в `.gitignore`); в `data/sample/` — только выдуманные образцы.
- Ключ BotHub и токен Moodle лежат в `.env`, который в `.gitignore` и не попадает в git.
- Файл преподавателя из реестра скачивается только в память, на диск не сохраняется.
- Streamlit работает только на `localhost`, телеметрия отключена.
- Текст загруженного файла (кроме файлов Aiken) отправляется в BotHub для обработки моделью.
  Не загружайте файлы с персональными данными студентов; допустимость передачи материалов
  стоит согласовать с ИМЭС.
